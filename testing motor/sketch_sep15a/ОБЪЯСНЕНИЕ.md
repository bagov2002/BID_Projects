# sketch_sep15a.ino — разбор

Arduino Uno + драйвер шагового двигателя (HY-DIV268N, вход STEP/DIR/ENA как у TB6600).
Двигатель ездит между двумя концевиками START ⇄ END по **экспоненциальному профилю скорости**
из ГОСТ Р ИСО 26782-2016, приложение C (таблица C.1, профили C1–C13).

Это не трапеция. Трапеция (см. `main/motor test.c`) плавно разгоняется и тормозит.
Здесь скорость в начале **максимальная**, а потом падает по экспоненте.

---

## 1. Что за профиль

Профили из приложения C описывают, как объём меняется во времени:

```
V(t) = FEV · [1 − e^(−t/τ)]
```

Скорость (поток) — производная:

```
Q(t) = dV/dt = (FEV/τ) · e^(−t/τ)
```

Поршень двигается так, чтобы его положение повторяло V(t). На графике: в момент t = 0
скорость наибольшая, потом она спадает всё медленнее (как разряд конденсатора).

Параметры профиля берутся из таблицы `profiles[]`: `τ` (постоянная времени) и `tFEV`
(время, за которое профиль заканчивается). Выбор — константой `PROFILE_NUMBER` (сейчас 2 = C2).

### Нормировка на ход

Физический ход в шагах задаёт `TRAVEL_STEPS` (20000). Чтобы за время `T = tFEV` пройти ровно
этот путь, формула делится на своё значение в конце:

```
доля пути:   x(t) = [1 − e^(−t/τ)] / [1 − e^(−T/τ)]          0…1
скорость:    v(t) = e^(−t/τ) / (τ · [1 − e^(−T/τ)])          доли хода в секунду
в шагах/с:   v(t) · TRAVEL_STEPS
период:      1 000 000 / (шагов в секунду)                    микросекунд
```

Это функции `gostPosition`, `gostSpeed`, `gostStepsPerSecond`, `gostPeriodUs`.

Пиковая скорость (при t = 0) для `TRAVEL_STEPS = 20000`:

| Профиль | τ, с | T, с | Начальная скорость | Период между шагами |
|---|---|---|---|---|
| C2 (по умолчанию) | 1.00 | 8.586 | ~20 000 шаг/с | ~50 мкс |
| C6 | 0.50 | 3.654 | ~40 000 шаг/с | ~25 мкс |
| C13 | 2.50 | 2.320 | ~13 200 шаг/с | ~76 мкс |

## 2. Разбор кода по блокам

### Пины и настройки (строки 27–84)
- `PUL_PIN 3`, `DIR_PIN 4`, `ENA_PIN 5` — вход драйвера. `LIM_START_PIN 6`, `LIM_END_PIN 7` — концевики.
- `TRAVEL_STEPS` — число шагов между концевиками. **Самый важный параметр**: от него зависят все скорости.
- `PUL_WIDTH_US` — ширина импульса STEP (5 мкс).
- `END_PAUSE_MS` — пауза на каждом конце. `DEBOUNCE_MS` — время антидребезга.

### Таблица профилей (строки 99–161)
Структура `GostProfile` хранит по одной строке таблицы C.1. `getProfile()` отдаёт выбранную.
Поля `exponentialVolume` и `riseTime_ms` **только печатаются** в `printProfile()`, в расчёте не
участвуют. Считаются только `tau` и `tFEV`.

### Концевики и антидребезг (строки 168–230)
- `rawStartHit()` / `rawEndHit()` читают пин. Срабатывание = **HIGH**. Пины с `INPUT_PULLUP`, значит
  концевики подключены как **нормально замкнутые (NC)** на GND: пока не нажаты — LOW, при нажатии
  или обрыве провода — HIGH. Это безопасная схема: обрыв воспринимается как срабатывание.
  Если поставить нормально разомкнутый (NO), программа сочтёт, что концевик нажат всегда.
- `debounceUpdate()` — состояние принимается, только если сырое значение не менялось `DEBOUNCE_MS`.
  Вызывается на каждом шаге внутри циклов движения.
- `limStartHit()` / `limEndHit()` отдают уже отфильтрованное значение.

### `setDir()` (строка 237)
Выставляет DIR и ждёт 10 мкс, чтобы драйвер успел «увидеть» направление до первого шага.

### `doStep(period_us)` (строка 378)
Один шаг: PUL = HIGH на 5 мкс, потом LOW, потом ждёт остаток периода. Полная длительность
шага = `period_us` **плюс время вычислений** (см. проблему ниже).

### `moveToEndGost()` и `moveToStartGost()` (строки 431 и 515)
Одинаковые, отличаются направлением и проверяемым концевиком:

1. Ставит DIR, запоминает время старта `micros()`.
2. В цикле:
   - `debounceUpdate()` и проверка концевика. **Концевик всегда главнее профиля**: сработал — выход.
   - `t` = время с начала движения.
   - Если `t < tFEV`: период берётся из профиля. Иначе — 5000 мкс (200 шаг/с) «доползание»
     до концевика, на случай если реальный ход длиннее `TRAVEL_STEPS`.
   - `doStep(period)`.
   - Раз в 500 мс печатает в Serial время, расчётный процент пути и скорость.

Профиль привязан **ко времени**, а не к числу пройденных шагов. Шаги не считаются.

### `setup()` (строка 590)
- Настраивает пины, включает драйвер (`ENA = LOW`), печатает профиль.
- 20 раз вызывает `debounceUpdate()`, чтобы фильтр «прогрелся».
- Если START не нажат — едет назад со скоростью 200 шаг/с, пока его не найдёт (поиск нуля).

### `loop()` (строка 675)
START → END (`moveToEndGost`) → пауза → END → START (`moveToStartGost`) → пауза → повтор.

## 3. Проблемы и слабые места

1. **Разгона нет.** В t = 0 скорость сразу максимальная (для C2 ~20 000 шаг/с). Шаговик с 0 так не
   стартует: без ускорения он пропустит шаги или зависнет (стоит на месте и гудит). Параметр
   `riseTime_ms` (время нарастания потока у настоящих кривых ГОСТ) объявлен, но не применяется.
2. **Uno не успевает считать.** На каждом шаге дважды вызывается `exp()` и делаются деления в
   `float`, а на 8-битном AVR это по оценке сотни микросекунд. Расчётный период 50 мкс
   недостижим: реальная скорость упрётся в скорость вычислений, а не в профиль. Замера я не делал.
3. **Ожидание после расчёта.** `doStep` ждёт `period` **после** вычислений, а не до заданного момента.
   Поэтому реальный период = период + время расчёта, и всё идёт медленнее профиля.
4. **Шаги не считаются.** Поскольку скорость привязана ко времени, при пропущенных или замедленных
   шагах поршень не пройдёт `TRAVEL_STEPS` и придёт к концевику позже, «доползая» на 200 шаг/с.
5. **Скачок скорости в конце.** Для C2 в момент `tFEV` расчётная скорость ~4 шаг/с, а потом
   включается «доползание» 200 шаг/с. Скорость наоборот **увеличивается**.
6. **Нет тайм-аута** ни на поиск START, ни на движение. Если концевик не подключён или подключён
   как NO — мотор будет ехать бесконечно (в поиске START) или упрётся в механику.
7. **Serial внутри цикла шагов.** Печать раз в 500 мс блокирует шаги на пару миллисекунд.

Возможные улучшения: считать шаги и считать профиль по позиции; заранее вычислить таблицу
периодов (в `setup`, в `float` или в таблице) вместо `exp` на каждый шаг; добавить короткий
линейный разгон в начале; использовать аппаратный таймер вместо `delayMicroseconds`.

## 4. Сравнение с трапецией из `main/motor test.c`

| | Трапеция (ESP32) | Экспонента ГОСТ (Uno) |
|---|---|---|
| Скорость в начале | 200 шаг/с, растёт | максимальная сразу |
| Привязка | к числу шагов | ко времени |
| Ускорение | постоянное, ограничено `ACCEL` | не ограничено |
| Остановка | по счёту шагов | по концевику |
| Риск пропуска шагов | низкий | высокий на старте |
